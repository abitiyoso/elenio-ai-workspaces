# Phase-based implementation & acceptance gates

Do not implement all phases in one Codex turn. Master prompt first executes 0 and 1, then owner visual review. For later turns use small phase prompts below. After each, test relevant code and push feature branch into owner's repo; never upstream/main/prod. Maintain live feature matrix/status, exact SHA/test artifacts, and ADRs for boundary decisions. If production config unavailable, test against explicitly labelled fixture/local disposable DB and report gap. Do not disable security or rewrite runtime for mockup. Baseline PRD contains FR and UAT IDs; add traceability and acceptance IDs below without dropping baseline requirements.

## Phase 0 — Git isolation, audit, architecture
Read Git guide, clone only to separate folder and private owner repo after rights/security checks. Evidence: login, private repo URL, source commit SHA, branch/remote guard, origin SHA (or clear blocker). Inventory actual routes/API contracts, package manifests/lockfiles, tests, current environment/deploy scripts, auth/tenant secrets handling, node/runtime capabilities, existing tool support and domain packs. Build live matrix (Existing-tested / Existing-unverified / Enhance / New / Blocked). Baseline lint/typecheck/unit/integration/build per module using current docs and disposable dependencies, do not run scripts blindly against live VM. Record tests and skipped items. ADRs: shared UI across React18/19 apps, project/context source, graph adapter and layout persistence, cost ledger ownership, customer packaging. No new big implementation before findings. Commit namespaced kit and audit, only safe references. Exit: verified remote isolation and scope with baseline/clear blockers.

## Phase 1 — Design system & flagship frontend slice (mandatory review)
Deliver shared tokens/primitives and component showcase, role-aware global/project shell and responsive nav, Home/Projects/Workflow Studio vertical slice, node inspector and Knowledge Hub redesign. Integration to existing GET/save/validate where safe; mock fixtures must be explicit, separate and must not claim backend. Existing routes/capabilities not removed. Implement React Flow + layout based on real `next`, typed ports and conditions; preserve canonical semantic roundtrip, layout independent. Conditional and parallel examples, editing node positions/connections, invalid graph diagnostic, fit/pan/zoom/minimap, keyboard/contextual inspector; subworkflow conditionally disabled. Layout title/breadcrumb compact, focus mode, no half-empty fixed graph. Knowledge workspace document-driven explorer, not rejected layout. Shared UI states. Provide screenshots at defined viewport sizes and actual defects resolved including mobile, use browser E2E test. Compare anti-reference and brand original assets. Commit/push branch, PR or checkpoint. **Stop for owner's acceptance of visual design and core UX**, do not proceed Phase 2 automatically. Gate can be completed with clearly labelled fixtures for unavailable services, never call that full production.

## Phase 2 — Core engineering / project orchestration
Prompt: "Read STATUS, product map, PRD relevant sections and UX spec. Implement Phase 2: integrate project lifecycle, Architect requirement discovery/blueprint/import/diff, manual graph edit/save/validate, reusable templates, agent/skills/tool bindings, knowledge and integrations through existing contracts. Preserve auth and versions; test and push owner branch."
Gate: one project context persists; AI Architect asks clarification and proposes minimal agents, dependency readiness and draft; user edits/diff-confirm -> valid graph. If real model unavailable, configuration error or explicit sandbox, never generic fake success. Manual and template paths equivalent. Roundtrip import/export `next/config/schema/policy` intact; unsupported mappings diagnostic. Agents/skills/tool drafts/versions and published bindings correct. KMS ingest/review/publish ACL retrieval; secure connector test and mapping using approved adapters first. Generic MCP/API gated and separately assessed. APIs integrated with actual sandbox services; tests for validation/concurrency/tenant boundary/unknown tool. No backend rewrite.

## Phase 3 — Evaluation/runtime/evidence & multi-model
Prompt: "Read source agent release contracts and engineering spec. Implement Phase 3: model/provider UI, approved deployment binding, scoped probes, agent playground/eval/release and workflow execution trace/approval integration. Verify real sandbox and evidence; push tested changes."
Gate: at least one configured approved or authorized sandbox provider real test, additional provider capability only when verified; dev mock explicit and release blocked. Same dataset for model comparison, schema/critical evidence/injection and self-approval failures, pinned versions. Agent release requester/domain reviewer/AI Ops independent, rollback new executions only. True/false branch, parallel join, workflow approval, draft rework, input/output/trace and KMS cited evidence, retry/cancel with no duplicate side effects. Actual run state from API/events, no synthetic concurrent claim. Preserve egress and scope. If credential unavailable, explicit integration blocker and fixture evidence only.

## Phase 4 — AI Economics & optimization
Prompt: "Implement AI Economics spec using verified telemetry and versioned rate cards; scenario estimator, ledger, cost drilldown, budget and baseline/TCO. Add deterministic tests and UI across architect, canvas, eval, operations. Push tested owner branch."
Gate: synthetic fixture exact values (see economics spec), branch and parallel/retries, actual vs scenario vs sandbox, missing-rate and zero-vol handling, idempotent scoped ledger, cost per attempted and completed, FX and amortization, ROI defined, quality not compromised, privacy/budget enforcement claims verified, source timestamps. Model rates editable/approved, no false provider support. Finance baseline and sample decision output; no invented real business savings.

## Phase 5 — Customer Business Workspace / release governance
Prompt: "Extend Universal Case Workspace and Control Plane app registry through existing contracts. Implement operator views, case intake, artifacts/evidence, human revision, approval and tasks, app entitlements, domain pack preview/startability. Verify pilot and publish PR."
Gate: user with business-only rights can't access builder; case owner can review/request revision and submit; proper reviewer approves/rejects with audit, stale artifacts reopen review; no fake auto approval. Domain pack SIM Tender representative with real bindings/config if available; vendor & recruitment proposed pilots built and tested in sandbox, no unauthorized ERP/ATS action or AI-only rejection. Distinguish unavailable fixtures; permissions and app registry consistent. Project linked to business-ready release/version; case pinned. No cross-tenant artifacts or data.

## Phase 6 — Portable deployment & enterprise delivery
Prompt: "Implement target portable delivery for customer runtime + business app and full private platform using existing scripts, documented dependency/identity topology, release package/build/manifests and validation. Verify clean isolated test environments, smoke & rollback. Do not deploy remotely without approval."
Gate: portable package contains signed/checksummed versioned definitions, dependencies, pinned images and SBOM, migrations, config schema, secret refs, target manifest, tests, docs/runbook/RACI, no customer docs/secrets. Docker/VM first, K8s later when validated; both managed and full private explicitly differentiated. Customer-selected model/API network boundaries; no undeclared cloud call/local asset CDN. Verify clean install, health, authorized case, failure/rollback, backup/restore, logs/metrics/security. A mock manifest is not deployment. Customer-specific production install requires explicit authorization and verification.

## Phase 7 — Production readiness and handover
Prompt: "Run cross-module regression, security/tenant and data governance, usability/responsive/accessibility, load/latency/reliability, backup/restore, end-to-end pilot and customer handover acceptance. Address failures without shortcuts. Produce release candidate MR/PR with measured evidence and blockers."
Gate: no critical failing tests or security/approval issues, all original PRD required UAT IDs mapped, regression passes, builder/operator roles correct, no placeholder dead actions, vendor+recruitment representative E2E (SIM as repository-backed additional sample when configured); actual costs reconciled and audit, versioned deployment and rollback; standard health/monitoring/runbook, handover. Explicit production go/no-go by owner and reviewers, not agent self-approval. Report exact known gaps and evidence.

## Common acceptance checklist (extend per phase)
- GIT-01 origin private correct owner, upstream push disabled, no destructive history changes; commits pushed & remote SHA confirmed; main not overwritten.
- UX-01 visual consistency, logo unchanged, light/gradients selective; screenshot browser evidence on desktop/tablet/mobile. UX-02 all visible actions meaningful or explicit unavailable; deep links and context persistence, error/empty/loading/permission states. UX-03 canvas fills viewport; graph 6–20 nodes and branching/parallel fit, keyboard, mobile review list. UX-04 Knowledge document-centric not sparse master/detail. UX-05 shared components and tokens no divergent custom theme patches.
- FLOW-01 semantic roundtrip preserving IDs,next,config,input_schema,policy/version; unsupported/invalid graph cannot run; FLOW-02 matched bypass exception, unmatched executes exception; split/join, approval/rejection/revision, no unauthorized action. FLOW-03 validate and publish restricted, immutable version pinning and rollback. FLOW-04 execution trace same graph/event source, no fictitious status.
- AI-01 approved model/profile binding with consent probe and version. AI-02 eval pinned suite, critical failures and dev mock block; independent release. AI-03 scoped skill/tool knowledge, bounded calls, schema/evidence flags. KMS-01 ingestion lifecycle, preview, scoped retrieval, revoked/expired data unusable.
- SEC-01 negative RBAC/tenant tests, delegated identity, no self-grants or approval bypass. SEC-02 secret/vault/log redaction, safe adapters/SSRF, idempotency and callbacks, sandbox no prod changes. SEC-03 version concurrency, audit and stale artifacts.
- ECON-01 exact fixture calculations; branch/retry and parallel distinct, rate version & missing data; ECON-02 attempted/completed, actual vs estimated, baseline/TCO/payback/ROI quality; duplicate/late events and tenant. ECON-03 limits/overrides and budget provenance; no hard-cap claims without enforcement.
- APP-01 operator view separated, case revision and independent approval, app launch/permissions. DEP-01 real deploy validation isolated runtime + full-platform config, secret injection, data residency; DEP-02 backup restore/rollback/health, runbook and provenance.

## Status checkpoint template
Phase / branch / upstream commit / origin remote SHA / PR URL; objective; changed components/contracts and ADR; tests commands + exact results and skipped reasons; screenshots and viewport; feature matrix updated; risks/blockers (runtime/prod unknowns); next phase scope. Keep concise, linked to files. Approval gate result explicitly recorded. Never promise unattended future work; resume via phase prompt.
