# UX and design system — Living Intelligence / Precision Studio

## Visual brief
Light-first by explicit user direction; premium, stylish, futuristic and not visibly AI-generated. Original Elenio logo assets in `references/brand-assets`: default logo for light, white versions when genuinely dark. Preserve aspect ratio, adequate clear space, do not redraw or generate replacements; keep Social and identity / Visual Languange references as brand source. Use actual assets locally, not random web logo placeholders. No forced full dark mode. Use design components as consistent foundation, not off-the-shelf visual identity. Benchmark n8n for editing, Linear for density/hierarchy, Notion for knowledge exploration, Langfuse for cost/trace, Spline for distinctive abstract visuals. These are inspirations; no brand copying or unlicensed assets. Latest V10 functional reference, V9 for cost/business flows; the user rejected the graph in V9 and Knowledge Hub V10, screenshots included. Do not clone those layouts.

## Tokens and foundations
Proposed CSS variables (reconcile with official guideline): canvas #F5F7FA, surface #FFFFFF, ink #112B4D, brand #2864EC, neutral secondary #64748B or verified contrast equivalent; functional colors for agent violet #8971DC, integration cyan/teal #42A8B5, success #36A486, human/approval amber #D8A052, error accessible red. Use saturated colors sparingly; labels always sufficient independent of color. 75% neutral, 20% pale accents, 5% saturated is a directional principle, not a quota. Signature gradients: soft intelligence #E4F1FF → #BCCDF9 → #D5C9FC, connectivity #E8F7FA → #A8DDE8, selective orchestration #123D80 → #376CDF → #947DE6. Gradient on meaningful visual art, not every card/button. Typographic hierarchy: one clear page title ~26–34px desktop, body ~13–16px per density, labels ≥12 where feasible; no micro-text aesthetic. Consistent fonts licensed for self-hosting. 4/8 spacing system, 8–12 subtle radii for controls, restrained shadows and borders. Contrast WCAG 2.2 AA target; visible focus, keyboard support, reduced motion, touch targets; small icon controls accessible name. Meaningful hover states and progress. Avoid hardcoding arbitrary page widths and inline style variants.

## Component foundation
Existing React/TS/Vite services have differing React versions (CP 19; Agent Studio/Flowcase 18 in inspected manifests). Recheck lockfiles and compatibility, make ADR; do not migrate entire stack for appearance. Use shared token package and styles/components with shadcn/ui + Radix primitives, Tailwind where appropriate, @xyflow/react for graph, ELK.js for layered DAG layout, Recharts for charts, Motion for functional animation, Lucide icon set. Alternatives only with written technical justification. Select dependencies deliberately, lock versions, check licenses, security, bundling/offline. Shared primitives: button/icon-button, input/select/combobox, dropdown, dialog/drawer, tooltip, tabs, breadcrumbs, sidebar, page header, expandable resizable inspector, toast, empty/loading/error/permission states, data table, searchable command palette, status, card only when semantically grouping, source/evidence badge, agent avatar, run/quality/cost chart. Document component states and usage; build a local component sandbox/gallery rather than pay for tool. Use existing working controls when safe; do not rewrite service API or auth for UI.

## Five composition archetypes
1. Launchpad (Home / Architect): compact central prompt + recent work + useful template entry, single signature live intelligence network that responds to selected use case; not landing page hero plus many stat cards. Chat/blueprint side by side when wide, tabs when narrow; upload, clarifications, assumptions, requirements, blueprint/dependencies, cost, button Build only after understood. Reveal actual state, undo/diff. No duplicated prompts or feature panels. AI Architect always accessible within project when useful.
2. Studio (Workflow/Agent/Testing): nearly full available viewport; title breadcrumb and slim command bar, graph canvas fills space. Inspector resizable, dismissible, context only. On-canvas plus and searchable node palette; avoid giant header and half-empty graph. Workflow: flexible infinite world (not fixed 760px), fit bounds on initial/load/manual fit, preserve zoom/pan and positions, horizontally flowing layered graph with actual branch geometry; no zig-zag by array order. Start/end ports only applicable ports, conditional labels true/false, parallel split/join distinct; separate dashed dependency edges (model/KMS/tools) from actual process edges. Drag connector, edit/reconnect/delete, selection multi-select if viable, undo/redo, keyboard actions, contextual menu, minimap, toolbar, accessible alternative list. Node configuration type-specific, tri-pane when needed: input, params, output, schema/test/issues; errors navigate to actual node. Agent identity abstract layered geometry, not identical blue robot icon; colors by capability. Create agent via chat or advanced editor with model, skills/tools, knowledge, budget, versions, evaluation. Testing shares topology; animate actual run events only, shows state, skipped paths and human stop; do not invent progress. Small screens favor readable list/node inspector/review (mobile editing if feasible, no unreadable mini graph).
3. Library (Knowledge/Templates/Models/Skills & Tools/Integrations): compact local navigation/filter, real searchable collection/document table/grid with useful density, detail drawer or full document/content view when selected; not two giant boxes with a few fields or fake counts. Knowledge: collection tree, search/filter document status/owner/revision/expiry, sortable file list, preview/source citations, ingest/retry, review/publish/revoke, permissions and retrieval playground in relevant tabs. Use page space to show actual content; no large generic 'source lifecycle' strip unless real status. Templates: preview graph and dependencies, clone/import validation. Models: provider/model status and rates/approval in coherent detail. Skills/tools: versions and bindings with schema, reuse. Integration: catalog, connection form, mapping, test output, policy and error. Avoid overdecorating forms.
4. Intelligence (AI Economics / Operations / Evaluation): meaningful cost/quality/latency charts, tables and filters with units/currency/time range and clear provenance. Side-by-side baseline vs estimated/actual, branch breakdown, per-node and token drilldown; selected run trace, reviews, failures; no fictional charts presented as telemetry. Charts keyboard/legend alternatives; loading/missing/unpriced states explicit. Gradient accent on selected chart/summary, not every tile.
5. Business Workspace (Case Apps): focus on business outcome, adaptable domain pack navigation, case progress, action queue, editorial artifact/document review surface, evidence/source rail, revision and submit/approve in context. Distinguish owner submit vs approver decide; show role and version; no builder tools for business user. Deployment target & data topology shown on separate relevant page rather than everywhere.

## Screen-specific non-negotiables
- Home: compact launch prompt and project resume; no dead promotional cards. Agent map supports click/search/filter and state; preserve useful sample scenarios.
- Project: persistent title, role/version/state and recommended next action computed from actual validation and pending dependencies. Lifecycle Discover/Design/Configure/Validate/Release/Operate/Optimize in overview, not excessive duplicate headers. Context persists across navigation and reload; deep links restore correct resource.
- Workflow: use >=80% practical available main area vertically in desktop focus mode (excluding necessary controls); inspector cannot consume canvas; no fixed width, orphan nodes visible. Test 6–20 nodes, branched/parallel, long labels, empty graph, error case. No page overflow; scroll/pan canvas distinct. Fit graph to viewport without tiny unreadable zoom limit; ability to zoom in. Inspect config based on actual `NodeType` and server validator. Nodes not supported by runtime clearly marked, cannot publish executable claim. Distinguish visual position metadata from canonical workflow config.
- Agent studio: distinguish Document Intelligence, Workflow Architect, Integration Specialist, Compliance Reviewer using consistent custom abstract visual identity. Richness confined to meaningful art; no new official logo. Agent graph shows relationships, trace view chronological.
- Knowledge: explicitly redesign rejected screenshot; left collection tree useful but not >30% desktop unless narrow; actual document list is focal; preview drawer opened only on select. Sources and indexing status consistent. Empty collection has single helpful CTA; no fabricated counts. Document ingest backend supports PDF per inspected contract; others labeled unsupported until implemented.
- AI Economics: editable variables with save/provenance and capped validity; nonnegative numbers, monthly volume zero handled; all currency/units readable, assumptions visible. Chart compare like-for-like quality/cost; report cost/run vs completed case. Model benchmark on same dataset; not fictional accuracy.
- Deployment: guided target choice, check dependencies, validation, signed version bundle, actual status; full private vs runtime-only explicit. Operations and approval focus queue, contextual drilldown, not generic dashboard.

## Visual QA and UX gates
Use actual browser screenshots on 1440x900, 1280x800, 1024x768, 768x1024, 390x844 (also 360 if possible), large screens 1920 if available. Evaluate content alignment, visual balance, legibility, truncation, keyboard focus, sidebar scrolling and no overlay blocking headings; responsive breakpoints not simply scale whole desktop. Explicit flow test: home→architect→project→canvas→condition→testing→approval→deploy; knowledge browse/search/preview; agent model selection; template cloning; case review; economics inputs; navigating away/back. Every visible action does real intended UI logic/API or explicit disabled explanation. Use browser console + screenshots and accessibility audit; include user-facing evidence by screen and actual findings, not self-scored 90/100 claims. No fake AI narration or production data. Visual acceptance gate owner reviews before further build.
